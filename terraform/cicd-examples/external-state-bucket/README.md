# Terraform state bucket

This bootstrap root creates a versioned S3 bucket and publishes its name as the
`terraform_state_bucket` SSM parameter. The IaC pipeline example uses that bucket for
Terraform state and pipeline artifacts.

The bucket is hardened for state storage: all public access is blocked, SSE-S3
encryption is declared explicitly, versioning is enabled, and a bucket policy denies any
request made without TLS. Server access logging is not configured to keep the bootstrap
simple; for production use, consider adding `aws_s3_bucket_logging` with a dedicated
access-logging bucket to audit state reads and writes.

```shell
terraform init
terraform plan
terraform apply
aws ssm get-parameter --name terraform_state_bucket
```

Deploy this root before `../iac-pipeline`.

## Cost

S3 charges for stored state versions and requests; Parameter Store standard parameters
have no additional charge. Add lifecycle rules appropriate for your recovery policy.

## Quotas

Confirm S3 bucket and SSM parameter quotas. Bucket names are generated by AWS and are
globally unique.

## Validation

Run `terraform fmt -check`, `terraform init`, `terraform validate`, and review
`terraform plan`. After apply, verify bucket versioning is enabled and the SSM parameter
contains the created bucket name.

## Cleanup

Destroy the IaC pipeline first. Empty all object versions from the bucket, then run
`terraform destroy`; S3 refuses to delete a non-empty versioned bucket.
